  즉시 텔레포트(걸어서 복도를 가로지르지 않음)
- **5절 Q&A 상호작용** — 방 진입 시 환영 토스트, 자유 질문 입력 → RoomData 기반 답변. 구현 방식(오프라인

  구체 스펙으로 고정

변경 없음 — 추가만 함, 원칙 #1·#3 준수).

## 2026-11-04 — 설계 보강: 심사 단계(기초조사·본심사·수정본검토·견본검수) 분류 추가

**상태**: 문서·데이터 스키마 갱신, 코드 구현 전

사용자 요청: 일자·역할 외에 "기초조사/본심사/수정본 검토/견본 검수" 단계별로도 인계인수서 데이터를
분류해 검색할 수 있게 해달라는 요청. 업로드되어 있던 실제 사업계획서(`abe70299-...txt` Ⅷ장)와
인계인수서(`9076dddc-...txt`)를 다시 읽어 4단계의 정의·실제 진행 방식·2024년 연간 일정 예시를
확인하고 근거로 삼음(추측으로 채우지 않음).

- `RoomData.cs`: `tasksByDay`(1단계 구조)를 `schedules: List<PhaseSchedule>`(2단계: 단계→일자→
  업무)로 변경. `ReviewPhase` enum(기초조사/본심사/수정본검토/견본검수) 추가.
- `GameManager.cs` / `SaveSystem.cs`: `CurrentPhase` 상태 추가, 저장 데이터에 `currentPhase` 포함.
- `Documents/개발명세서.md` 11절에 4단계 정의·실제 연간 일정 예시·검색 UI(단계 탭) 설계 추가, 2·5·9절
  갱신.
- **중요 발견**: 기초조사·본심사는 같은 합숙 시설에서 연속으로 진행되지만, 수정본 검토(6~7월)·견본
  검수(8월)는 완전히 다른 시기의 사무 검토 성격이 강함 — 이 두 단계가 지금과 동일한 7개 공간·5일
  합숙 구조를 그대로 쓰는지는 아직 확인되지 않아 "결정 필요 사항"에 추가함.
- 이 스키마 변경 시점엔 Unity 에디터에서 만든 실제 `RoomData` 에셋이 아직 없으므로(1단계 샘플룸도
  그레이박스 전) 마이그레이션 이슈는 없음.
