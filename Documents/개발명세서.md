# 개발 명세서 — 가상 업무 인계인수 공간

조건: Unity 6 LTS · URP · Windows 64-bit 스탠드얼론 · 1인칭 · 아바타 없음 · 싱글 사용자.
(이전에 검토했던 Unity 2022 LTS·3인칭·NPC 아바타 버전 설계안은 폐기하고 이 문서로 대체한다.)

## 1. 공간 설계

호텔 합숙 공간을 기준으로 한 복도형 1자 배치를 그대로 따른다. 실측치가 없을 경우 아래 권장 치수를
기준으로 삼는다(엑셀·도면이 확보되면 그 값으로 교체).

| 공간 | 권장 치수(가로×세로×층고) | 비고 |
| --- | --- | --- |
| 심의회실(오벌테이블 8인) | 6.5m × 5.0m × 2.6m | 중형 호텔 연회장 1실 |
| 운영팀·진행팀(책상 6~7대) | 5.5m × 4.0m × 2.6m | 호텔 마스터스위트 |
| 기획팀·외부지원팀 | 4.5m × 3.6m × 2.6m | 호텔 주니어스위트 |
| 자료보관실(운영팀 내 분할) | 2.5m × 2.0m × 2.6m | 운영팀 일부 파티션 |
| 소통공간(라운지) | 5.0m × 4.0m × 2.6m | 로비 라운지 |
| 복도 | 폭 1.8~2.2m, 천장고 2.6m | 호텔 객실복도 |

## 2. 비품 데이터 모델

```csharp
[CreateAssetMenu(menuName = "Camp/RoomData")]
public class RoomData : ScriptableObject {
  public string roomId;
  public string label;
  [TextArea] public string roleDescription;
  public Vector3 size;
  public string nestedInRoomId;      // 자료보관실 → "operation"
  public List<FurnitureEntry> furniture;
  public List<DailyTask> tasksByDay; // d1, d2, mid, e1, e2
}

[System.Serializable]
public class FurnitureEntry {
  public string kind;      // desks, shelf, table, tv, whiteboard, printer, crate, sofa, cooler
  public Vector3 localPos;
  public string label;
  public bool interactable;
}
```

비품 종류(kind)별 프리팹 매핑:

| kind | 예시 | 비고 |
| --- | --- | --- |
| desks | 데스크탑 PC·듀얼모니터 | 책상+의자+PC+모니터 복합 프리팹 |
| table | 심의 회의테이블, 라운지 테이블 | 오벌테이블 + 의자 7조 |
| shelf | 도서서가, 자료 서가 | 책 스핀 여러 개 + 사다리 |
| tv | TV(PC 연결) | 벽에 거치, Render Texture |
| whiteboard | 화이트보드 | 포스트잇 메모 부착 가능한 메시 |
| printer | 컬러복합기, A4 프린터 | 단일 메시 |
| crate | 합숙 물품 박스, 보안/창고 물품 | Rigidbody 적용 가능 |
| sofa | 소파 | 단일 메시 |
| cooler | 정수기 | 단일 메시 |

## 3. 상호작용 기능

모든 조작 가능 오브젝트는 `IInteractable`을 구현한다. 1인칭이므로 화면 중앙 기준 Raycast로
2m 이내 접근 시 아웃라인 하이라이트 + "E키로 상호작용" 프롬프트가 뜬다.

| 오브젝트 | 조작 | 결과 |
| --- | --- | --- |
| 컴퓨터(모니터) | E → 화면 UI 전환 | 해당 역할의 일자별 업무 체크리스트 표시 |
| 화이트보드 | E → 마커 팔레트 UI | 텍스트/스티커 메모 작성, 메모 형태로 저장·불러오기 |
| 서가(책장) | E → 책 제목 리스트 UI | 업로드된 사업계획서·인계인수서 등 실제 문서를 PDF로 연결 |
| TV | E → 콘텐츠 전환 | 일정·공지사항을 Render Texture로 순환 표시 |
| 크레이트/박스 | E → 열기 애니메이션 + 내용물 툴팁 | 퇴소1·퇴소2일차 라벨(평가원행/창고행) 연동 |
| 정수기·소파 | 상호작용 제외 | 분위기 요소 |

아바타가 없으므로, 직전 설계안의 "NPC가 인사말을 건네는" 연출은 **컴퓨터/TV 화면의 환영 문구**로
대체한다(첨부 레퍼런스 이미지의 "Welcome to Virtual Office" 참고).

## 4. 공간 선택·이동 구조 (허브 + 텔레포트)

사용자 확인: "원하는 공간을 클릭하면 그 공간 내부로 들어가서 탐방하는" 흐름이 핵심이다. 걸어서
전체 복도를 가로지르는 것이 아니라, **허브(평면도/미니맵)에서 방을 고르면 그 방으로 바로
텔레포트**한다.

- 미니맵(화면 우상단 원형, UI 레퍼런스 스펙 참고)에 전체 평면도와 플레이어 현재 위치(화살표 아이콘)를
  표시한다. 평면도 자체를 클릭 가능한 UI로 만들어 방 영역을 누르면 해당 방으로 이동한다.
- 별도로 홈(로비) 화면에 방 목록 카드형 UI를 둬서 미니맵 없이도 선택할 수 있게 하는 방안도 고려한다
  (최종 UI는 2차 결정 사항).
- 구현: `SceneLoader.LoadRoom(roomId)` 호출 → 해당 방 서브씬을 Additive 로드 → `RoomData`의
  `spawnPosition`/`spawnYaw`로 `Player`를 이동 → 이전 방 서브씬은 Unload.
  이동 중에는 짧은 페이드 아웃/인(검정 화면 0.3~0.5초) 연출로 로딩을 가린다.
- 좌상단 홈 버튼을 누르면 언제든 허브(평면도 화면)로 즉시 복귀한다.

## 5. 공간 내 Q&A 상호작용

각 방에 들어가면(위 텔레포트 직후) 화면 좌상단에 말풍선형 환영 토스트가 떠서 안내 문구를 보여주고
몇 초 뒤 자동으로 사라진다("가상 업무 공간에 오신 것을 환영합니다! 필요한 자료를 찾아보세요." 형태,
레퍼런스 이미지 참고).

플레이어는 화면 하단 텍스트 입력창(또는 별도 호출 패널)에 자유롭게 질문을 입력할 수 있고, 그 방의
`RoomData`(역할 설명·비품 리스트·일자별 업무)를 근거로 답변을 받는다. 예: "여기서 뭘 준비해야 해?" →
현재 `GameManager.CurrentDay` 기준 그 방의 `tasksByDay` 목록을 답변으로 구성.

**구현 방식은 아직 미결정 — "9. 결정된 사항" 참고.**
- (a) RoomData 기반 오프라인 규칙/키워드 매칭 — 네트워크 불필요, 저사양·싱글유저 원칙에 가장 부합
- (b) 실제 LLM API 호출 — 더 자연스러운 자유 질의응답이 가능하지만 네트워크 연결이 전제되어야 함

## 6. 기술 아키텍처

- Unity 6000.x LTS + URP. Shader Graph 기반 NPR 보정 없이, 세미 리얼리스틱 PBR 재질 + 베이크드 GI로
  가벼운 사실감을 낸다.
- 씬 구조: 부트스트랩 씬 1개(로비·전역 매니저) + 방별 서브씬을 Addressables로 Additive 로딩.
- 카메라/입력: 1인칭 전용, 신규 Input System(WASD 이동 + 마우스 시점, 패드 지원은 후순위).
- 저장 방식: 싱글 유저이므로 서버 불필요. `Application.persistentDataPath`에 진행 상태를 JSON으로
  저장·복원.
- 성능: 실시간 라이트 최소화, 베이크드 라이트맵 중심, GPU Instancing 활성화, 텍스처 2K 이하 권장.

## 7. 에셋 소싱 플랜

완전 자체 제작보다 검증된 에셋 구매 + 부분 커스텀으로 시작한다.

| 영역 | 방향 |
| --- | --- |
| 오피스 가구·소품 | Unity Asset Store 사실적 오피스 팩 구매 후 색상·비율만 2절 데이터에 맞춰 조정 |
| 조명/셰이더 | URP 기본 Lit 셰이더 + Shader Graph 툴업(비노클로스/브룸) |
| UI/폰트 | Pretendard 폰트 그대로 사용(TextMesh Pro에 임베딩) |

## 8. 로드맵 (초안)

1. **프로젝트 부트스트랩**(현재 단계) — 폴더 구조, 코어 스크립트, 그레이박스 샘플룸 1곳
2. **프로토타입** — 샘플룸에서 1인칭 이동·상호작용·베이크드 라이팅 파이프라인 확정
3. **전체 공간 제작** — 7개 방 배치, 실제 가구 에셋 입히기
4. **상호작용·UI 폴리싱** — 체크리스트/자료함/교육자료 패널 실제 기능 연결
5. **QA·빌드** — 저사양 최적화, Windows 빌드 검증

## 9. 결정된 사항 / 남은 결정 사항

- 빌드 타겟: **Windows 64-bit 스탠드얼론** (확정)
- 카메라 시점: **1인칭** (확정)
- 아바타: **없음** (확정)
- 방 이동 방식: **허브/미니맵에서 클릭 → 텔레포트** (확정, 4절 참고)
- 남은 것:
  - 실제 방 치수·비품 수량을 실측 도면/엑셀로 교체할지
  - 1단계 샘플룸 이후 어떤 방부터 실제 아트를 입힐지(심의회실 우선 제안)
  - Q&A 구현 방식: RoomData 기반 오프라인 규칙 매칭 vs 실제 LLM API 연동(5절 참고) — 네트워크 연결
    허용 여부에 달려 있어 사용자 확인 필요
  - 방 선택 UI: 미니맵 클릭형 vs 로비 카드 목록형, 혹은 둘 다

## 10. UI/비주얼 레퍼런스 스펙 (첨부 이미지 기준)

"저 이미지 느낌 그대로"를 목표로, 레퍼런스 이미지에서 확인되는 요소를 구현 스펙으로 고정한다.
아래는 **의도와 레이아웃 정의**이며, 실제 포토리얼한 결과물은 로컬 에디터에서 Asset Store 가구팩 +
라이트맵 베이크로 완성해야 한다(3D 아트 자체를 생성하는 것은 이 세션의 범위 밖 — CLAUDE.md "세션
제약" 참고).

**공간 톤앤매너**
- 벽: 따뜻한 화이트~베이지 톤, 한쪽 포인트월은 우드 패널(세로 루버 느낌)
- 바닥: 밝은 우드 플로어링, 평행 플랭크 패턴
- 천장: 백색 마감 + 사각 우물천장 안에 warm LED 간접조명 스트립, 원형 스팟조명 2~3개, 천장형 공조
  디퓨저 1개
- 가구: 화이트~라이트그레이 프레임의 사무 가구(책상·회의테이블·의자 전부). 목재 포인트는 책상
  상판 정도로 최소화 — 벽·바닥의 우드톤과 중복되지 않게 가구는 화이트 계열로 대비를 준다
- 장식: 블루·네이비 계열 추상화 액자 1점, 벤자민/올리브 트리류 화분을 방 곳곳에 다수 배치
- 핵심 집기 배치: 중앙 대형 회의테이블(8~10인) + 의자, 정면 벽 TV(브랜드 환영 슬라이드 표시),
  이동식 화이트보드(포스트잇 부착), 좌우 사이드 책상(모니터+프린터), 빌트인 책장/캐비닛(서류
  바인더 정리됨), 원두머신 올린 서랍장

**HUD(화면 오버레이) 레이아웃**
| 위치 | 요소 | 비고 |
| --- | --- | --- |
| 좌상단 | 홈 버튼(원형 아이콘) | 눌러서 허브(평면도)로 즉시 복귀 |
| 좌상단, 홈 버튼 옆 | 말풍선형 알림 토스트 | 방 진입 시 환영 문구 1~2줄, 수 초 후 자동 소멸 |
| 우상단 | 원형 미니맵 | 현재 층 평면도 + 플레이어 위치 화살표, 클릭 시 해당 방 텔레포트 |
| 좌하단 | 조작키 안내 카드 | WASD 이동 / 마우스 시점회전 / E 상호작용 / ESC 메뉴, 반투명 다크 카드 |
| 하단 중앙 | 원형 아이콘 버튼 4개 | 자료함 · 교육자료 · 체크리스트 · 설정 |

전체적으로 톤온톤 반투명 다크 카드 + 화이트 텍스트 + 둥근 모서리로 통일한다. 이 HUD는 Canvas
(Screen Space - Overlay)로 구성하고, 미니맵은 별도 Top-down 카메라 + Render Texture로 만든다
(둘 다 에디터 작업 — 다음 단계 가이드 문서에서 단계별로 안내 예정).
